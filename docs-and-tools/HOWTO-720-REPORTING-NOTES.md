# הערות ליחידה הזאת על `HOWTO-720-REPORTING.md`

הערה נלווית ל-`HOWTO-720-REPORTING.md` שבשורש. **המדריך עצמו לא שונה במכוון** —
הוא מיועד להיות מועתק כמות שהוא ליחידות חדשות, ולכן הוא לא צריך לשאת הערות
ספציפיות ליחידה אחת. ההערות האלה יושבות כאן, ב-`docs-and-tools/`, שאינו נפרס
ואינו מועתק.

הקובץ נכתב ב-2026-09-01, אחרי שהמדריך נוסף ב-`5cf704e`.

---

## מה שאינו טעות, ואין "לתקן" אותו

המדריך מתאר את `40-ledger.js` ואת יומן ה-`completed` ב-`sessionStorage`.
**זה מכוון, לא מיושן.** §0 ("מה לא צריך") קובע במפורש שה-resume מחוץ להיקף ושהמדריך
מניח `RESUME_ENABLED = false`, ו-§4.1 מצביע על `40-resume.js` כמסלול השדרוג.
פרקי הארכיטקטורה עקביים בתוך עצמם ונכונים לבסיס הזה.

נרשם כאן כי בקריאה ראשונה זה נראה כמו תיעוד שלא עודכן — וזו מסקנה שגויה שקל
מאוד להגיע אליה שוב.

## מה כן שבור — מקור ההעתקה

הפסקה הפותחת של המדריך ("מה להעתיק מיחידה שכבר עברה את התהליך") מורה להעתיק את
`unit-js/` — שישה קבצים — ולשנות **ארבע שורות**. היחידה הזאת היא כרגע המועמדת
הטבעית להעתיק ממנה, והיא כבר עברה את שלב ה-resume ב-`1584d49`. לכן ההוראה
נשברת מולה:

| המדריך מניח | ביחידה הזאת בפועל |
|---|---|
| `40-ledger.js`, 179 שורות | `40-resume.js`, 653 שורות |
| היומן ב-`sessionStorage` | היומן בתוך מסמך ה-State API |
| `RESUME_ENABLED = false` | `RESUME_ENABLED = true` (`unit-js/10-identity.js:60`) |
| `LEDGER_STORAGE_KEY` — אחת מארבע השורות | **לא קיים כלל** |
| `NAV_EDGE_KEY` — השורה הרביעית | קיים, אבל ב-`unit-js/40-resume.js:403` |

שתי התוצאות של העתקה עיוורת:

1. **יחידה חדשה עם resume דלוק** ובלי ארבעת ה-hooks הפר-רכיביים שהוא דורש
   (`capturePartPayload` / `applyResumeVars` / `applyResumeDom` /
   `restoreScreenUI`). זו בדיוק האזהרה שב-§4.1, רק מהכיוון ההפוך: לא "אל
   תדליקו את הדגל", אלא "הדגל כבר דלוק".
2. **אחת מארבע השורות לא נמצאת.** `LEDGER_STORAGE_KEY` אינו קיים באף קובץ
   ב-`unit-js/` כאן. זו הנקודה שבה הקורא מפסיק לסמוך על שאר המדריך — וזה הנזק
   האמיתי, יותר מהשורה החסרה עצמה.

## שני מסלולים תקינים

**1. הבסיס של המדריך — מומלץ ליחידה חדשה.**

```bash
git show 1584d49^:unit-js/40-ledger.js > <יחידה חדשה>/unit-js/40-ledger.js
```

ואז להעמיד `RESUME_ENABLED = false` ב-`10-identity.js`. חמשת הקבצים האחרים
עוברים כמות שהם, וכל שאר המדריך מדויק מילה במילה.

אומת: הפקודה מחזירה את הקובץ המלא (179 שורות, שני מפתחות האחסון בפנים),
ו-`10-identity.js` באותו commit נושא `RESUME_ENABLED = false` — כלומר הבסיס
שהמדריך מתאר, בדיוק.

**2. עם resume.** לקחת את `40-resume.js` כמות שהוא, להשאיר
`RESUME_ENABLED = true`, ולממש את ארבעת ה-hooks בכל רכיב. זה **מחוץ להיקף
המדריך**; העיצוב המלא ב-`RESUME.md` כאן, וששת הסינים של היחידה הזאת הם
המימוש לדוגמה.

## מלכודת נוספת בהעתקה

טבלת ההעתקה מפנה גם ל-`_test/verify-report.js` ("לשנות: ה-slug ורשימת
הרכיבים"). בהרנס של היחידה הזאת יש מאז גם בדיקות שתלויות ב-resume ובמצב
התשובות — שחזור מיקום בועיות המשוב, חתימת התשובה שנשלחה, וחיווט כפתורי הבדיקה.
ביחידה חדשה שרצה בלי resume הן לא רלוונטיות ויש להסיר אותן, לא רק להחליף את
ה-slug.
